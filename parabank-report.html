Average response time

The HTTP 429

The first 10-user run with a 25 s ramp-up returned 429 Too Many Requests. The identical configuration, rerun, finished with 0% errors and a 458 ms average.

The 429 did not reproduce, so no rate-limit threshold is claimed. Possible causes, all unconfirmed: cumulative requests from my IP during earlier debugging, other traffic on the shared server, or time-window rate limiting.

Limitations

  • Shared public server, so results include network and server variability.
  • One run per configuration, 7 samples per user.
  • Indicative numbers, not a capacity benchmark.
  • Balance conservation under concurrent load was not verified.

Next steps

  • Self-host ParaBank and test 25, 50 and 100 users.
  • Add the balance-conservation check across transfers.
  • Capture Retry-After and X-RateLimit headers if a 429 recurs.
